# 财报分析数据接入交互模板

目标：降低客户尝试门槛。客户只需要提供文件或文件位置；报告口径、期间、公司名、三表识别、模板选择等由后续流程自动处理，只有确实无法判断时才少量追问。

## 默认客户话术

当用户说"分析某家公司财报 / 生成财务分析报告 / 看一下某公司经营情况"，但没有提供文件、路径或授权数据源时，只回复以下简短话术：

```text
可以，请把财报文件直接发给我，或者告诉我文件/文件夹在哪里。

Excel、CSV、PDF、Word、图片或压缩包都可以先发来；我会先检查文件能否读取，后续按默认流程处理。
```

这就是默认入口话术，不再另列长清单，也不在入口阶段追问报告口径、期间、三表、KPI 或模板。

## 不要在入口阶段追问这些

除非用户主动要求，否则入口阶段不要问：

- 报告口径
- 分析目标
- 报告期间
- 公司全称
- 行业
- 利润表/资产负债表/现金流量表是否齐全
- 经营数据、预算、KPI、模板是否提供
- 输出格式或报告结构

这些内容由后续解析、三表校验和模板流程自动识别。识别失败时，再针对单个问题追问。

## 什么时候才搜索本地

只在以下情况搜索：

- 用户明确说"在本地找一下 / 搜一下"；
- 用户给了具体目录或文件路径；
- 当前 workspace 中已经有明确相关的上传文件。

## 搜索边界

- 有路径：只搜该路径。
- 无路径：先问用户希望搜哪个目录；兜底只搜当前 workspace。
- 不要搜 `/`、整个 home 或无边界递归搜索。
- 多个候选文件时，列少量候选让用户选，不要擅自混用。

## 上传文件后的处理

收到任意文件（不论是上传还是从路径读取），先完成文件读取检查，再进入财报分析。内部使用 `scripts/FinClaw parse-upload.py` 做读取校验：

```bash
python3 /root/.hermes/skills/data-reporting/finclaw-financial-analysis-runner/scripts/FinClaw parse-upload.py <file_or_dir> [--json-out out.json]
```

随后按输入形态决定是否加一层格式适配：

- `.xlsx` / `.xlsm` / `.csv` / `.tsv`，或已经可读的 MaybeAI Sheet 结构化数据：直接进入原 FinClaw 主流程。
- `.xls` / `.docx` / 文字层 PDF / ZIP / 多文件夹 / 图片 / 扫描 PDF：先调用 `data-reporting/document-ingestion`，仅用于产出 `extracted_tables`、`extracted_text`、`source_manifest`、`issues`，再交给原主流程。
- 如果 `document-ingestion` 返回 `requires_ocr`、`missing_dependency` 或 `unsupported_format`：不要生成正式财报报告，先让用户做 OCR、转换格式、补充文件或安装依赖。

注意：`document-ingestion` 不生成报告结论，不替代三表底座，不替代管理分析，不改变 MaybeAI Sheet 最终结构。

如果文件无法读取，客户侧只说明原因和下一步建议，不暴露内部状态字段或技术细节。

## 回复模板

### 文件都已读取
"资料我已经收到并完成读取。接下来我会按默认流程做财报校验和分析。"

### 部分资料需要补充
"有几份资料我已经可以使用；另外几份还需要补充处理：
- <文件名>：<简短原因，例如：图片内容需要先转成可读取的表格>

我可以先基于已读取的资料继续分析；未读取到的部分会在报告中说明为数据暂未提供。"

### 当前资料暂时不能读取
"这份资料我目前还不能直接读取，原因是：
- <文件名>：<简短原因>

你可以换成 Excel 或 CSV 再发我；如果需要，我也可以继续尝试其他导入方式。"
