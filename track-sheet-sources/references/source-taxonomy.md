# Track Sheet Sources Taxonomy

Use this file only when source classification is not obvious from the evidence.

## Source types

### `web`

Use when the value is supported by a directly opened webpage, PDF page, document page, or canonical article URL.

### `database`

Use when the value comes from a database query or durable warehouse/table result with identifiable rows, fields, or query context.

### `api`

Use when the value comes from a structured API, database response, or tool result with stable fields.

### `tool`

Use only when the tool output is the closest stable provenance surface the assistant can inspect and the deeper upstream source is not recoverable.

Do not use `tool` as a blanket source type just because a tool wrote the worksheet. Tools are execution methods. Classify the primary source by the upstream evidence:

- workbook writer such as `openpyxl`, Excelize, or MaybeAI Sheet write API -> classify by the generated data's upstream source, not by the writer
- search tool result without opening the canonical page -> `search`
- browser/opened page extraction -> `web`
- API client or API-backed MCP tool -> `api`
- database query tool -> `database`
- file/PDF/parser tool -> `file` or `document`
- model-generated synthetic/demo content -> `llm` with `upstream_source_type=synthetic`

When a tool still matters for auditability, keep it inside `source_refs[]` with `source_type="tool"`, `tool_name`, `tool_role`, and `upstream_source_type`, but keep the row-level `source_type` set to the upstream source.

### `file`

Use when the value comes from an uploaded file, retrieved file, spreadsheet attachment, local document, or parsed PDF/docx section.

### `document`

Use when the value comes from a document-like source that is not best modeled as a raw file, such as a managed knowledge-base document, doc page, or indexed document section.

### `search`

Use when the value is supported only by search snippets or search results, not by an opened canonical page.

### `multimedia`

Use when the value comes from audio, video, image OCR, transcript timestamps, or media-derived analysis.

### `llm`

Use when the value is model-derived, guessed, summarized without stable evidence, or otherwise unsupported.

Use `llm` for synthetic or demo data generated by the assistant when no real external source backs the exact value. Since `sheet_cell_metadata.source_type` does not currently include `synthetic`, represent synthetic/demo data as:

```json
{
  "source_type": "llm",
  "source_refs": [
    {
      "source_type": "tool",
      "tool_name": "openpyxl",
      "tool_role": "workbook_writer",
      "upstream_source_type": "synthetic",
      "section": "synthetic financial model generation"
    }
  ]
}
```

### `mixed`

Use when one cell materially combines more than one source type and you cannot fairly collapse it into a single primary type.

### `user`

Use when the value was explicitly provided by the user.

## Tie-break rules

1. Prefer `web` or `api` over `search` only after verification.
2. Prefer `file`, `api`, `database`, `web`, `search`, or `llm` over `tool` whenever the tool's upstream source is recoverable.
3. Prefer `llm` over pretending there is a real source.
4. If a tool generated synthetic/demo values, use row-level `source_type=llm`, not `tool`.
5. If the cell has one strong source and one weak source, keep the strongest real source as primary and mention the weaker one in `note` or extra rows.

## Tool role taxonomy

When preserving tool evidence in `source_refs[]`, set `tool_role` where possible:

| tool_role | meaning | primary row-level source_type |
| --- | --- | --- |
| `workbook_writer` | wrote values/styles to the spreadsheet | upstream source, often `llm`, `file`, `api`, or `database` |
| `calculator` | computed formulas, ratios, pivots, sanity checks, or reconciliation | source of inputs; use `llm` only for synthetic inputs |
| `extractor` | extracted values from file, document, OCR, or page content | `file`, `document`, `multimedia`, or `web` |
| `searcher` | returned search results or snippets | `search` unless a canonical page was opened |
| `api_client` | called a structured API | `api` |
| `database_client` | ran a database or warehouse query | `database` |

## Bad pattern from real case

Do not create an entire workbook with:

```json
{
  "source_type": "tool",
  "confidence_level": 2
}
```

for every cell merely because a script generated the workbook. Instead, split cells by upstream origin and audit role:

- synthetic financial assumptions -> `source_type=llm`, `upstream_source_type=synthetic`
- workbook formulas or calculated ratios -> source type of inputs, with `tool_role=calculator`
- generated disclaimers and "demo data" labels -> `source_type=user` when explicitly requested, or `llm` when assistant-authored
- values copied from uploaded files -> `file`
- values from opened public reports/pages -> `web`
